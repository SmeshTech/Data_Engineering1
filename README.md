# 🛒 Kasi Mart Data Engineering Project 1

## 📌 Project Overview

This project demonstrates the use of **Snowflake and SQL** to build a simple retail data environment for Kasi Mart.

The project focuses on creating a database and tables, loading structured retail data, validating the data, and using SQL queries to generate meaningful business insights.

The project was completed using **Snowflake** as the primary data platform.

---

## 🛠️ Technologies Used

* **Snowflake** – Database and data warehouse platform
* **SQL** – Database creation, data loading, transformation and analysis
* **GitHub** – Version control and project submission

---

## 🗄️ Database Structure

The project uses the following database and schema:

```text
Database: DE_PROJECT1
Schema: PUBLIC
```

Three tables were created:

### 1. CUSTOMERS

Stores customer information.

| Column        | Data Type |
| ------------- | --------- |
| CUSTOMER_ID   | STRING    |
| CUSTOMER_NAME | STRING    |
| EMAIL         | STRING    |
| PROVINCE      | STRING    |
| SIGNUP_DATE   | DATE      |

### 2. PRODUCTS

Stores product information and pricing.

| Column       | Data Type |
| ------------ | --------- |
| PRODUCT_ID   | STRING    |
| PRODUCT_NAME | STRING    |
| CATEGORY     | STRING    |
| UNIT_PRICE   | NUMBER    |

### 3. ORDERS

Stores customer purchase transactions.

| Column      | Data Type |
| ----------- | --------- |
| ORDER_ID    | STRING    |
| CUSTOMER_ID | STRING    |
| PRODUCT_ID  | STRING    |
| ORDER_DATE  | DATE      |
| QUANTITY    | NUMBER    |

## 🔄 Data Relationships

The tables are connected using customer and product identifiers.

```text
CUSTOMERS
   │
   │ CUSTOMER_ID
   ▼
ORDERS
   │
   │ PRODUCT_ID
   ▼
PRODUCTS
```

The `ORDERS` table acts as the central transaction table, connecting customers with the products they purchased.

# 🔍 SQL Analysis

Four SQL queries were developed to analyse the retail data.

## Query 1: Order Details and Line Revenue

This query joins the `ORDERS`, `CUSTOMERS`, and `PRODUCTS` tables to display each order together with the customer name, product name, category, quantity, unit price, and calculated line revenue.

The calculation used was:

```sql
quantity * unit_price AS line_revenue
```

This provides a detailed view of individual transactions and demonstrates the use of **SQL JOINs and calculated fields**.

---

## Query 2: Total Revenue per Customer

This query calculates the total revenue generated by each customer.

It uses:

* `JOIN`
* `SUM()`
* `GROUP BY`
* `ORDER BY`

The results help identify customers who generate the highest revenue and can support customer segmentation and retention strategies.

The query returned **49 customers with orders**. One customer, **Sam Naidoo**, had no recorded orders.

---

## Query 3: Total Revenue per Product Category

This query calculates the total revenue generated by each product category.

### Results

| Category    | Total Revenue |
| ----------- | ------------: |
| Beauty      |       R87,081 |
| Home        |       R72,904 |
| Fashion     |       R49,800 |
| Electronics |       R47,562 |

**Beauty** generated the highest revenue, while **Electronics** generated the lowest revenue among the four categories.

This analysis can help support decisions around inventory management, promotions, product performance and sales strategy.
